This is the bounded O4E Resume verification scenario. Run real tools from scratch, not a simulation or code review. Use Chinese for brief progress and reporting. This is a fresh noninteractive Session with no existing Tasks. Finish after the bounded protocol; the harness owns process cleanup.

1. Your FIRST tool must be `task`, with exactly these arguments: `{"subagent_type":"inspect-child","description":"Production resume live acceptance","prompt":"Follow your complete system protocol: public BEGIN paragraph, first guarded wait, public MIDDLE paragraph, second guarded wait, all 100 long STREAM lines and completion marker. No replacement, retry or restart."}`. Omit `background`. Create exactly one Task. No status/list preflight, replacement, retry, restart, cancel, questions or permission replies.
2. Immediately call `o4e_task inspect` for its actual taskID with `maxBytes:128,direction:forward,resume:false`. Continue sequential progress reads with `inspect`, `maxBytes:128,direction:forward,resume:true`, at most 30 inspect calls total. Observe actual BEGIN and MIDDLE public text only from inspect. If watch returns `user-message`, stop and report interrupted so the real user message can be handled first. Stop immediately and report incomplete on any other error or exhausted budget. Do not call cancel; the harness owns cleanup.
3. On a completed watch result, collect `output` once with only `action` and `taskID`; do not request reread and require the public tool body to be the result text itself. Do not supply cursor/cursors, call a batch fixture, insert other reads between these four, or retry a failed sequence.

Report the distinct real Part sequence, admitted/completed waits, inspect gaps/unavailable, fresh recoveries and any user-message interruption.
